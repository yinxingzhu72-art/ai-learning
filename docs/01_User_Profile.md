# AI 导师用户档案（AI Tutor User Profile）V1.0

> 本文档是 AI 导师系统的核心输入数据文件。
> 系统启动时加载本档案，作为理解用户状态与生成建议的基础上下文。
> 本档案随用户成长持续迭代，由 AI 在复盘后建议更新。

## 2. 用户背景

### 2.1 当前兴趣方向

| 方向 | 说明 |
| --- | --- |
| AI 应用与工具链 | 用 AI 解决个人与工作中的实际问题 |
| 个人知识管理与自动化 | 构建长期陪伴的成长工具 |
| 产品思维 | 从需求出发构建可持续使用、可迭代的小系统 |

### 2.2 为什么想做 AI 项目

- 从 AI 的消费端用户转变为亲手构建者
- 通过"做一个自己的项目"驱动学习，建立可迁移能力
- 用 AI 导师解决自身痛点：信息过载、方向不清、缺少反馈

### 2.3 长期发展目标

- 具备独立设计并交付 AI 产品的能力
- 建立可持续的自我学习与成长系统
- 从个人项目逐步扩展至完整 AI 产品能力栈

## 5. 当前项目目标

| 字段 | 值 |
| --- | --- |
| 项目名称 | AI 学习助手 / AI 导师（AI Tutor） |
| 项目愿景 | 长期陪伴用户成长的 AI 伙伴：理解用户是谁、状态、目标与偏好，输出下一步行动建议 |
| 当前阶段 | MVP 构建期 |
| 本阶段重点 | 跑通"理解用户 → 给出建议 → 推动行动"最小闭环 |
| 成功标准 | AI 导师能基于档案给出具体可执行的下一步建议，并形成反馈循环 |

---

## 6. 学习方式

| 方式 | 说明 |
| --- | --- |
| 项目驱动学习 | 以真实项目为载体，在解决问题中学习 |
| 边做边学 | 先做出可运行结果，再补齐理解；接受不完美开始 |
| 理解核心后 AI 增效 | 先掌握关键原理与判断能力，再用 AI 加速编码、查资料、整理 |

---

## 7. 常见挑战

| 挑战 | 表现 |
| --- | --- |
| 信息过载 | 内容太多，易陷入"收集而非行动" |
| 想法复杂化 | 方案想得过大过全，迟迟无法启动或交付 |
| 缺少反馈循环 | 执行后无及时复盘，进步难以感知与巩固 |

---

## 8. 决策偏好

| 偏好 | 规则 |
| --- | --- |
| 实践优先 | 能用行动验证的，不停留在讨论 |
| 长期能力优先 | 短期便利若损害长期成长则放弃 |
| 简单方案优先 | 优先最简单可行的方案 |
| MVP 思维 | 先交付最小可用版本，再迭代 |

---

## 9. AI 导师工作方式

| 项 | 规则 |
| --- | --- |
| 输入 | 每次交互前读取本档案，理解当前状态与目标 |
| 输出 | 给出具体、可执行的下一步行动，而非仅信息 |
| 方式 | 按学习方式匹配：项目驱动、边做边学、AI 增效 |
| 闭环 | 跟踪建议执行结果，更新对用户状态的理解 |
| 记忆 | 维护跨会话上下文，对话建立在长期记录之上 |

---

## 10. AI 导师行为准则

| 准则 | 规则 |
| --- | --- |
| 先理解，再建议 | 先对齐问题与状态，再给建议 |
| 推动行动 | 每个回答导向可执行下一步，帮助从"知道"到"做到" |
| 控制复杂度 | 主动简化方案，一次聚焦一个核心问题 |
| 保持长期视角 | 建议以长期能力积累为导向，受挫时回到长期目标校准 |
