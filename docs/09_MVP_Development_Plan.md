# AI Tutor MVP 开发路线（AI Tutor MVP Development Plan）V1.0

> 本文档定义 AI Tutor 如何从设计阶段进入实际开发阶段：开发目标、阶段规划、最小版本定义与学习路线。
> 前置文档：01 用户设计、02 使用场景、03 MVP 功能设计、04 用户流程、05 技术架构、06 数据库设计、07 API 设计、08 Prompt 设计。
> 面向 AI 应用开发初学者，不使用过度复杂技术描述。

---

## 1. 开发目标

### MVP 的意义

- MVP（Minimum Viable Product）：以最小工作量交付可验证核心价值的产品
- V1 不追求功能完整，而是验证核心价值

### AI Tutor V1 核心验证目标

验证 AI 是否能够帮助用户：

- 理解当前状态
- 明确目标
- 推进项目
- 找到下一步行动

若以上闭环可跑通并产生价值，则 MVP 成功，继续迭代；否则调整方向。

---

## 2. 开发原则

| 原则 | 规则 |
| --- | --- |
| 小步迭代 | 先完成小闭环，再逐渐增加能力；每阶段有可运行产出 |
| 核心功能优先 | 优先实现：用户理解、数据管理、AI 建议 |
| 简单优先 | 避免复杂架构、过度设计、企业级功能 |

## 3. 开发阶段规划

### Phase 0：开发环境准备

| 项 | 内容 |
| --- | --- |
| 目标 | 能够运行基础项目 |
| 学习内容 | VS Code、Git 基础、Python 环境、Node.js 环境 |
| 开发内容 | 项目初始化（前后端目录结构、Git 仓库、环境配置） |
| 阶段产出 | 可运行的空项目骨架，能跑通 Hello World |

### Phase 1：基础应用框架

| 项 | 内容 |
| --- | --- |
| 目标 | Frontend / Backend / Database 三模块能通信 |
| 学习内容 | Next.js 基础、FastAPI 基础、数据库连接 |
| 开发内容 | 前端页面基础结构、后端 API 服务、数据库连接 |
| 阶段产出 | 前端页面可调用后端 API，后端可读写数据库 |

### Phase 2：用户数据系统

| 项 | 内容 |
| --- | --- |
| 目标 | 系统能够保存用户状态 |
| 学习内容 | 数据模型实现、CRUD 操作 |
| 开发内容 | 实现核心数据对象：User、Profile、Goal、Project、Task |
| 阶段产出 | 用户可建立档案、创建目标与任务 |

**为什么这一阶段优先**：AI 建议依赖用户数据。没有 User/Profile/Goal/Project/Task，AI 无上下文可用，后续阶段无法进行。

### Phase 3：AI 接入

| 项 | 内容 |
| --- | --- |
| 目标 | 用户可以和 AI 交流 |
| 学习内容 | LLM API 调用、AI Service 封装 |
| 开发内容 | 模型 API 调用、AI Service、基础 Prompt |
| 阶段产出 | 对话闭环可用：用户输入 → Backend → 调用 AI → 返回结果 |

### Phase 4：AI Tutor 核心闭环

| 项 | 内容 |
| --- | --- |
| 目标 | 实现核心能力："我今天应该做什么？" |
| 学习内容 | Context 组装、场景 Prompt、建议保存 |
| 开发内容 | 读取 Profile / Goal / Project / Task / Memory → 生成 Context → Prompt → AI 建议 → 保存 Recommendation |
| 阶段产出 | AI Tutor 核心能力完成：AI 能基于用户状态给出下一步行动 |

### Phase 5：成长记录系统

| 项 | 内容 |
| --- | --- |
| 目标 | 用户成长数据形成 |
| 学习内容 | 记录模型、Memory 提炼规则 |
| 开发内容 | Growth Log、Memory 实现与写入逻辑 |
| 阶段产出 | AI 能长期理解用户（参考历史成长，保持一致性） |

### Phase 6：体验优化

| 项 | 内容 |
| --- | --- |
| 目标 | 提升日常使用体验 |
| 学习内容 | 前端交互、错误处理、Prompt 效果调优 |
| 开发内容 | 优化 UI、交互、Prompt 效果、错误处理、性能 |
| 阶段产出 | 完整闭环可日常稳定使用 |

**为什么体验优化放在后面**：先保证功能闭环可用、价值可验证；在功能不完整时优化体验是浪费。体验优化在核心闭环成立后进行，效果才能被真实使用检验。

## 4. MVP 最小版本定义

V1 必须实现的闭环：

```
用户
    ↓
建立档案
    ↓
设置目标
    ↓
创建项目
    ↓
创建任务
    ↓
请求 AI 建议
    ↓
保存成长记录
```

- 完成该闭环即可证明产品价值
- 闭环中每一步都对应 Phase 2-5 的开发内容
- 超出该闭环的功能（复盘、长期分析等）可后置

## 5. 开发顺序背后的原因

### 为什么先设计产品？

- 避免技术驱动但没有用户价值
- 先明确"为谁解决什么问题"，再决定技术方案

### 为什么先设计数据库？

- AI 需要理解用户状态，而状态存于数据库
- 数据结构决定 AI 能读到什么上下文

### 为什么 API 在 AI 前？

- API 是系统连接层（Frontend ↔ Backend ↔ Database）
- 没有 API，AI 服务无法获取数据、无法被前端调用

### 为什么 Prompt 不应该最先设计？

- Prompt 依赖 Context，Context 来自数据与接口
- 没有数据与接口，Prompt 无从设计、无法测试

### 为什么 MVP 不追求功能最多？

- 需要快速验证核心价值
- 功能越多，验证越慢，返工风险越高

### 开发逻辑

```
产品（要解决什么）
    ↓
数据（需要存什么）
    ↓
接口（如何读写）
    ↓
AI（如何分析与建议）
    ↓
优化（如何更好用）
```

## 6. 学习路线设计

面向 AI 应用开发初学者，每阶段与开发阶段对应。

| 阶段 | 主题 | 学习目标 | 实际应用 |
| --- | --- | --- | --- |
| 阶段 1 | Python 基础 | 掌握语法、函数、数据结构 | 编写后端逻辑与 AI 服务 |
| 阶段 2 | HTML / CSS / JavaScript | 掌握页面结构与基础交互 | 搭建前端页面骨架 |
| 阶段 3 | React 基础 | 组件化开发、状态管理 | 实现工作台 Dashboard |
| 阶段 4 | FastAPI | 路由、请求响应、模型校验 | 实现后端 API 服务 |
| 阶段 5 | 数据库和 SQL | 建表、增删改查、关系查询 | 实现数据持久化 |
| 阶段 6 | LLM API 调用 | 请求模型、解析返回 | 实现 AI Service 与对话 |
| 阶段 7 | Prompt 和 AI 应用设计 | Context 组装、场景化 Prompt | 实现 AI 建议核心闭环 |

说明：学习路线与开发阶段并行——每个开发阶段先学对应技能，再动手实现。

## 7. V1 暂不实现

| 内容 | 原因 |
| --- | --- |
| 多 Agent | 单 Agent 足够跑通闭环，多 Agent 增加复杂度 |
| 自训练模型 | 现成 LLM API 足够，训练成本高且非核心 |
| 复杂 RAG | V1 结构化上下文够用，向量库后置 |
| 社区系统 | 单人使用，无社交需求 |
| 企业权限 | 单用户系统，简单登录即可 |
| 商业化系统 | 当前为个人项目，无付费/运营需求 |

以上功能在核心闭环验证成立后，按需逐步引入。

## 8. 成功标准

完成后系统应该支持：

- ✅ 创建档案
- ✅ 创建目标
- ✅ 管理项目
- ✅ 管理任务
- ✅ 与 AI 交流
- ✅ 获得行动建议
- ✅ 保存成长记录

全部满足即 AI Tutor V1 MVP 交付完成。
