# AI 导师使用场景文档（AI Tutor User Scenarios）V1.0

> 本文档定义 AI 导师系统面向核心用户「杏珠（AI 应用开发方向学习者）」的完整使用场景。
> 每个场景描述触发条件、用户状态、处理逻辑、输出与需要持久化的数据。
> 本文档是功能设计与数据模型设计的输入。

---

## 场景一：创建新目标

### 1. 场景名称

创建新目标

### 2. 触发条件

- 用户提出一个新想法，例如"我想开发一个 AI 项目"
- 用户明确表示"我想定一个目标 / 立一个 flag"
- 用户在复盘后提出调整或新增目标

### 3. 用户当前状态

- 有模糊的想法或方向，尚未结构化成可执行的目标
- 可能同时有多个念头，未分清主次

### 4. 用户真实需求

- 把一个模糊想法转化为清晰、可执行、可验证的目标
- 确认这个目标值得做（价值判断）
- 知道第一步从哪里开始

### 5. AI 处理逻辑

1. 收集信息：用提问澄清想法、动机、预期成果
2. 明确目标：将想法重述为"一句话目标 + 可验证的成功标准"
3. 分析价值：评估目标对长期发展目标的支撑关系
4. 定义用户：确认该目标服务谁（自己 / 特定人群），需求是否真实
5. 确定 MVP 范围：划出最小可行范围，砍掉非必要部分
6. 产出初始行动建议，写入目标档案

### 6. AI 输出内容

- 一句话目标描述
- 价值分析结论（为什么做 / 为什么现在做）
- 目标用户定义
- MVP 范围清单（做 / 不做）
- 建议的下一步行动

### 7. 系统需要记录的数据

| 数据 | 说明 |
| --- | --- |
| 目标名称与描述 | 一句话目标 |
| 成功标准 | 可验证的完成定义 |
| 价值分析 | 与长期目标的关联 |
| 目标用户 | 服务对象定义 |
| MVP 范围 | 做与不做的边界 |
| 创建时间 | 目标创建时间戳 |
| 初始状态 | 创建时的用户状态快照 |

## 场景二：每日启动与行动规划

### 1. 场景名称

每日启动与行动规划

### 2. 触发条件

- 用户打开 AI 导师，询问"今天应该做什么"
- 用户标记某个目标"今天想推进"

### 3. 用户当前状态

- 处于一个或多个进行中的目标
- 可能有多个候选任务，不确定优先级
- 对"今天做什么"缺乏清晰判断

### 4. 用户真实需求

- 快速获得今日可执行行动的明确建议
- 知道先做什么、做多久、做到什么程度算完成
- 减少每天重新决策的成本

### 5. AI 处理逻辑

1. 读取输入：当前目标、项目状态、历史执行记录
2. 识别缺口：对比"目标进度"与"最近行动"，找出当前最该推进的点
3. 生成行动：产出一到三个具体行动项（不是任务列表轰炸）
4. 设定执行参数：每项给出时长、完成标准
5. 建立当日计划记录，等待执行反馈

### 6. AI 输出内容

- 今日行动项列表（建议不超过 3 项）
- 每项的：行动描述 / 预计时长 / 完成标准
- 优先级说明（为什么先做这个）
- 可选的"最低可行执行"提示（状态差时的保底动作）

### 7. 系统需要记录的数据

| 数据 | 说明 |
| --- | --- |
| 当日计划 | 行动项、时长、完成标准 |
| 计划生成依据 | 基于哪些目标与历史记录 |
| 计划时间 | 生成时间戳 |
| 执行结果 | 待用户反馈后回填（完成 / 部分 / 未做） |

## 场景三：问题解决

### 1. 场景名称

问题解决

### 2. 触发条件

- 用户描述遇到技术问题（报错、不会实现、不知道用哪个方案）
- 用户面临方向选择（继续 / 换方案 / 砍需求）
- 用户表达卡住、焦虑、想放弃

### 3. 用户当前状态

- 处于执行中，遇到阻力
- 可能被细节困住，或对方向产生动摇

### 4. 用户真实需求

- 快速定位问题，得到可执行的解决方案
- 判断这个困难是否影响整体目标（避免被小问题带偏）
- 需要情绪上的确认：这很正常，且有路可走

### 5. AI 处理逻辑

1. 收集问题描述，必要时追问关键细节
2. 分类问题类型：技术实现 / 方向选择 / 资源不足 / 状态问题（疲惫、失去动力）
3. 评估影响：该问题是否阻碍当前目标 / MVP 交付
4. 生成方案：
   - 技术问题 → 给出具体解决路径或排查步骤
   - 方向问题 → 对比选项，给推荐与理由
   - 状态问题 → 降低执行强度，给保底动作
5. 更新项目状态记录

### 6. AI 输出内容

- 问题类型判定
- 对目标影响程度的判断
- 推荐方案（含理由）
- 最小下一步（一个动作，越小越好）
- 必要时：放弃 / 缩减范围的建议

### 7. 系统需要记录的数据

| 数据 | 说明 |
| --- | --- |
| 问题描述 | 用户原始描述 |
| 问题类型 | 技术 / 方向 / 资源 / 状态 |
| 影响评估 | 是否阻碍目标 |
| 推荐方案 | 给出的解决路径 |
| 解决结果 | 待回填：是否解决、耗时 |

## 场景四：阶段复盘

### 1. 场景名称

阶段复盘

### 2. 触发条件

- 用户主动要求："帮我复盘一下最近这段时间"
- 达到设定周期（每周 / 每里程碑）
- 完成一个里程碑或 MVP 版本

### 3. 用户当前状态

- 完成了一段连续执行，需要回顾
- 对"自己到底进步没有"缺乏客观感知

### 4. 用户真实需求

- 客观看到这段时间做了什么、学到什么
- 确认能力变化，获得继续下去的正反馈
- 明确下一阶段方向，避免原地打转

### 5. AI 处理逻辑

1. 拉取周期内的执行记录、问题记录、完成事项
2. 汇总完成事项与学习内容
3. 对比周期前后状态，识别能力变化（显性技能 / 隐性认知）
4. 给出下一阶段方向与目标调整建议
5. 将复盘结论写入成长记录

### 6. AI 输出内容

- 完成事项清单
- 学习内容总结
- 能力变化判断（提升 / 稳定 / 待加强）
- 下一阶段方向与建议目标

### 7. 系统需要记录的数据

| 数据 | 说明 |
| --- | --- |
| 复盘周期 | 起止时间 |
| 完成事项 | 从执行记录汇总 |
| 学习内容 | 涉及的主题与知识点 |
| 能力变化 | 对比结论 |
| 下一阶段方向 | 调整后的计划 |
| 复盘时间 | 时间戳 |

## 场景五：长期成长分析

### 1. 场景名称

长期成长分析

### 2. 触发条件

- 周期性触发（月度 / 季度）
- 用户主动要求："看看我这几个月的成长"
- 目标发生重大调整时

### 3. 用户当前状态

- 已积累一段较长的使用记录
- 需要宏观视角判断成长方向是否正确

### 4. 用户真实需求

- 看到长期能力变化趋势，而非单点事件
- 验证当前方向是否值得继续投入
- 获得对未来几个月方向的高层建议

### 5. AI 处理逻辑

1. 聚合长期记录：目标、执行、问题、复盘、能力评估
2. 分析能力变化趋势：哪些能力持续上升、哪些停滞、哪些反复
3. 交叉分析：目标完成度与投入方向是否一致
4. 生成长期结论与方向建议
5. 更新用户档案中的能力状态

### 6. AI 输出内容

- 能力变化趋势（上升 / 稳定 / 停滞）
- 关键成长点与瓶颈
- 方向有效性判断
- 下阶段长期建议

### 7. 系统需要记录的数据

| 数据 | 说明 |
| --- | --- |
| 分析周期 | 起止时间 |
| 能力趋势数据 | 各维度变化 |
| 关键结论 | 成长点 / 瓶颈 |
| 方向建议 | 长期调整建议 |
| 档案更新 | 写入用户档案的能力状态 |

## 核心使用循环

```
用户状态变化
    ↓
AI 理解状态
    ↓
AI 判断下一步
    ↓
用户执行
    ↓
系统记录成长
    ↓
（回到顶部，进入下一轮循环）
```

说明：

- 五个场景分别是该循环在不同环节的体现
- 场景一、二：进入循环（设定目标、规划行动）
- 场景三：循环中的异常处理（执行受阻时回到判断环节）
- 场景四、五：循环的复盘环节（沉淀成长数据，反哺后续判断）

## 场景总结表

| # | 场景 | 触发 | AI 核心动作 | 关键记录数据 | 输出 |
| --- | --- | --- | --- | --- | --- |
| 1 | 创建新目标 | 用户提出新想法 | 明确目标 / 分析价值 / 定义用户 / 定 MVP 范围 | 目标、成功标准、MVP 范围 | 目标定义 + 下一步行动 |
| 2 | 每日启动与行动规划 | 用户询问今日行动 | 读目标与历史，生成优先级行动 | 当日计划、执行结果 | 今日行动项（≤3 项） |
| 3 | 问题解决 | 用户报告问题 / 卡住 | 分类问题、评估影响、推荐方案 | 问题、类型、方案、结果 | 类型判定 + 推荐方案 + 最小下一步 |
| 4 | 阶段复盘 | 周期或用户主动 | 汇总执行与学习，对比能力变化 | 复盘结论、下一阶段方向 | 复盘报告 + 方向建议 |
| 5 | 长期成长分析 | 周期或用户主动 | 聚合长期记录，分析能力趋势 | 趋势数据、结论、档案更新 | 长期分析报告 |
