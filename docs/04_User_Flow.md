# AI 导师用户流程设计（AI Tutor User Flow）V1.0

> 本文档定义 AI 导师 V1 的完整用户流程：用户如何开始使用、AI 如何理解用户、用户如何推进项目、AI 如何提供建议、系统如何记录状态变化。
> 对应功能定义见 03_MVP_Features.md，数据模型字段以该文档为准。

---

## 1. 核心用户流程概览

AI 导师核心循环：

```
用户状态变化
    ↓
AI 理解状态
    ↓
AI 判断下一步
    ↓
用户执行
    ↓
系统记录成长
    ↓
AI 更新理解
    ↓
（回到顶部，进入下一轮循环）
```

循环说明：

| 环节 | 内容 |
| --- | --- |
| 用户状态变化 | 目标、项目、任务、能力任一状态变化 |
| AI 理解状态 | 读取 User Profile / Goal / Project State / History |
| AI 判断下一步 | 生成下一步行动建议（推荐任务 / 原因 / 完成标准） |
| 用户执行 | 用户按建议行动，或自行推进 |
| 系统记录成长 | 更新 Task / Project State / Growth Log |
| AI 更新理解 | 将新状态纳入后续决策上下文 |

所有子流程（2-7 节）都是该循环在具体场景下的实例化。

## 2. 第一次使用流程（Onboarding Flow）

### 用户触发

- 用户第一次打开 AI 导师
- 系统无 User Profile 记录

### 用户目标

让 AI 理解：

- 用户是谁（身份 / 定位）
- 用户当前能力（技能水平）
- 用户目标（长期目标 + 第一个项目目标）
- 学习方式

### AI 流程

```
1. 欢迎用户
    ↓
2. 收集用户信息（身份 / 能力 / 目标 / 学习方式）
    ↓
3. 建立 User Profile
    ↓
4. 创建第一个 Goal
    ↓
5. 生成初始项目状态
    ↓
6. 进入工作台
```

| 步骤 | 动作 | 产出 |
| --- | --- | --- |
| 1 | 欢迎并说明系统能力 | 引导对话开始 |
| 2 | 提问收集信息 | 结构化用户信息 |
| 3 | 写入 User Profile | Profile 记录 |
| 4 | 明确目标与成功标准 | Goal 记录 |
| 5 | 生成初始阶段与首个任务 | Project State + 首个 Task |
| 6 | 展示工作台 | 进入日常使用 |

### 输出结果

工作台首屏展示：

- 用户状态（当前阶段 / 技能水平）
- 当前目标（标题 / 成功标准）
- 当前阶段（项目进度）
- 下一步行动（推荐任务 / 原因 / 完成标准）

## 3. 每日使用流程（Daily Flow）

### 用户查看

- 当前目标
- 项目状态
- 今日任务

### AI 处理

| 步骤 | 动作 | 输入 |
| --- | --- | --- |
| 1 | 读取上下文 | User Profile |
| 2 | 读取上下文 | Goal |
| 3 | 读取上下文 | Project State |
| 4 | 读取上下文 | History（近期待办 / 已完成） |
| 5 | 生成行动建议 | 今日最高价值行动（≤3 项） |

### AI 生成

| 输出 | 说明 |
| --- | --- |
| 今日最高价值行动 | 当前最值得做的一项 |
| 推荐原因 | 为什么先做这个 |
| 完成标准 | 做到什么程度算完成 |

### 完成后更新

用户执行完成后，系统更新：

- Task：status → done，写入 completed_time
- Project State：progress / current_stage 更新
- Growth Log：追加完成事项与学习内容

## 4. 项目推进流程（Project Flow）

### 流程链路

```
目标
 ↓
项目
 ↓
任务
 ↓
完成
 ↓
更新状态
```

### 包含环节

#### 项目创建

- 目标明确后，为 Goal 创建对应 Project
- 记录：name / current_stage / progress / status

#### 阶段划分

- 将目标拆解为阶段（V1 建议 3-5 个阶段）
- 每个阶段有明确完成标准
- 当前只推进一个阶段

#### 任务生成

- 当前阶段拆解为任务
- 每项任务含：优先级 / 完成标准
- 一次聚焦 1-3 个任务，其余进入待办

#### 状态更新

- 任务完成 → 更新 Task 状态
- 阶段完成 → 推进 current_stage，更新 progress
- 项目完成 → status → done，触发复盘（见 02 场景四）

## 5. 遇到问题流程（Problem Solving Flow）

### 原则

- AI 不直接给答案，先完成分析
- 每个问题都评估对目标的影响

### AI 处理步骤

```
1. 理解问题
    ↓
2. 判断问题类型
    ↓
3. 分析是否影响当前目标
    ↓
4. 提供建议
    ↓
5. 生成下一步行动
```

### 问题类型

| 类型 | 示例 |
| --- | --- |
| 技术问题 | 报错 / 实现方式 / 工具使用 |
| 产品问题 | 功能设计 / 需求取舍 |
| 方向问题 | 是否继续 / 是否换方案 / 是否砍需求 |
| 学习问题 | 学什么 / 怎么学 / 学不动 |

### 输出格式

```
当前问题
    ↓
原因分析
    ↓
推荐方案
    ↓
下一步行动
```

| 输出项 | 说明 |
| --- | --- |
| 当前问题 | 问题重述（确认理解一致） |
| 原因分析 | 问题根因 + 类型判定 |
| 推荐方案 | 推荐做法与理由 |
| 下一步行动 | 一个最小可执行动作 |

## 6. AI 决策流程（AI Decision Flow）

说明：AI 在以下时机主动分析并决策。

### 用户提出新想法

AI 判断归属：

| 判断 | 处理 |
| --- | --- |
| 新目标 | 走创建新目标流程（02 场景一） |
| 当前项目延伸 | 评估是否纳入当前项目范围 |
| 临时兴趣 | 记录为待办 / 暂不推进 |

### 用户请求建议

AI 依据以下数据判断下一步：

- 用户档案
- 当前目标
- 项目状态
- 历史记录

### 用户偏离目标

AI 分析：

| 分析项 | 判定 |
| --- | --- |
| 是否有价值 | 值得投入则记录 |
| 是否影响当前目标 | 影响则提醒优先级 |
| 是否应该延期 | 不影响则建议延期 |

### 用户长期卡住

AI 分析可能原因：

| 原因 | 调整动作 |
| --- | --- |
| 任务过大 | 拆分为更小任务 |
| 技术困难 | 提供解决路径或降级方案 |
| 目标不清 | 回到目标澄清 |
| 缺少反馈 | 安排阶段复盘或小里程碑 |

## 7. 异常流程设计

### 用户改变目标

| 要求 | 处理 |
| --- | --- |
| 保存历史目标 | 原 Goal 归档，不删除 |
| 支持修改目标 | 可修改 title / description / target_date / status |
| 支持创建新项目 | 新目标可关联新 Project，旧 Project 归档 |

### 用户长期未使用

- AI 不责备用户，不施压
- 重新确认三项：
  - 是否继续目标
  - 是否修改目标
  - 是否暂停目标

### 项目范围无限扩大

AI 提醒三项：

- 当前目标（回到目标本身）
- MVP 边界（03_MVP_Features.md 第 6 节）
- 优先级（当前最值得做什么）

## 8. V1 用户流程总结

AI 导师通过以下链路完成完整陪伴：

```
认识用户
    ↓
管理目标
    ↓
推进项目
    ↓
解决问题
    ↓
记录成长
    ↓
持续优化
```

| 链路环节 | 对应流程 | 关键产出 |
| --- | --- | --- |
| 认识用户 | Onboarding Flow（第 2 节） | User Profile |
| 管理目标 | AI 决策流程（第 6 节） | Goal 记录与更新 |
| 推进项目 | Project Flow（第 4 节） | Project State / Task |
| 解决问题 | Problem Solving Flow（第 5 节） | 建议 + 下一步行动 |
| 记录成长 | Daily Flow 完成更新（第 3 节） | Growth Log |
| 持续优化 | 异常流程 + 核心循环（第 1、7 节） | AI 更新理解，进入下一轮 |

结论：V1 的目标是让用户在"目标 → 行动 → 反馈 → 成长"的循环中持续运行，AI 在每个环节提供基于上下文的分析与建议。
