# AI Tutor 技术架构设计（AI Tutor Technical Architecture）V1.0

> 本文档定义 AI 导师 V1 的技术架构：四层结构、模块划分、数据存储、AI 接入方式与开发学习路线。
> 目标不是构建复杂企业系统，而是用简单、可靠、可学习的技术实现完整 AI 应用闭环。
> 数据模型与 03_MVP_Features.md 保持一致。

---

## 架构设计目标

V1 架构目标：

- 非复杂企业系统，非过度设计
- 使用简单、可靠、可学习的技术栈
- 实现完整 AI 应用闭环

核心流程：

```
用户输入
    ↓
系统读取用户状态
    ↓
调用 AI
    ↓
生成建议
    ↓
保存结果
    ↓
更新成长记录
```

---

## 1. 整体系统架构

四层架构：

```
┌─────────────────────────────────────────┐
│ 1. Frontend 用户界面层                     │
│    Next.js / React                        │
│    （登录、工作台、对话、成长记录）           │
└──────────────────┬──────────────────────┘
                   │ HTTP (API)
┌──────────────────▼──────────────────────┐
│ 2. Backend 服务逻辑层                     │
│    FastAPI                               │
│    （用户 / 目标 / 项目 / 任务 / AI 调用）  │
└────────┬────────────────────┬───────────┘
         │                    │
         ▼                    ▼
┌──────────────────┐  ┌──────────────────┐
│ 3. Database      │  │ 4. AI Layer      │
│    数据存储层      │  │    人工智能能力层   │
│    PostgreSQL    │  │    LLM API       │
└──────────────────┘  └──────────────────┘
```

数据流说明：

| 流向 | 内容 |
| --- | --- |
| Frontend → Backend | 用户操作、对话消息（HTTP 请求） |
| Backend → Database | 读写用户 / 目标 / 项目 / 任务 / 记录数据 |
| Backend → AI Layer | 携带上下文的 Prompt，调用 LLM API |
| AI Layer → Backend | 返回 AI 建议结果 |
| Backend → Frontend | 页面数据与 AI 建议响应 |
| Database → AI Layer | 由 Backend 读取后组织进上下文（不经前端） |

## 2. Frontend 前端设计

### 作用

- 负责用户交互与信息展示
- 向 Backend 发起请求，展示返回数据
- 不直接访问数据库、不直接调用 AI

### 页面

| 页面 | 功能 | 展示内容 |
| --- | --- | --- |
| 登录页面 | 用户进入系统 | 登录 / 注册入口 |
| AI Tutor 工作台 Dashboard | 主界面 | 用户信息、当前目标、项目状态、当前任务、AI 建议 |
| AI 对话页面 | 与 AI 导师交流 | 对话消息流、AI 建议输出 |
| 成长记录页面 | 查看成长历史 | 完成任务、学习记录、阶段总结 |

---

## 3. Backend 后端设计

### 作用

- 连接前端、数据库、AI 模型三端
- 承载业务逻辑与数据校验

### 模块

| 模块 | 职责 | 对应数据 |
| --- | --- | --- |
| 用户管理模块 | 用户信息、用户档案的读写 | User / User Profile |
| 目标管理模块 | 创建、修改、查看目标状态 | Goal |
| 项目管理模块 | 项目阶段、项目进度管理 | Project |
| 任务管理模块 | 创建任务、更新任务状态 | Task |
| AI 调用模块 | 组织上下文、构建 Prompt、调用 AI 模型、返回结果 | Conversation / Memory 输入 |

AI 调用模块为后端核心：负责把数据库中的用户状态组织成 LLM 可理解的 Prompt，并解析返回结果。

## 4. Database 数据库设计

### 作用

- 作为 AI 导师的长期记忆
- 保存全部业务数据，供 Backend 与 AI 上下文读取

### 保存内容

| 数据 | 来源模型（03 文档） |
| --- | --- |
| 用户信息 | User |
| 用户档案 | User Profile |
| 目标 | Goal |
| 项目 | Project |
| 任务 | Task |
| 对话记录 | Conversation |
| 成长记录 | Growth Log |
| AI 记忆 | Memory |

### 一致性要求

- 表结构、字段名与 03_MVP_Features.md 第 3 节数据模型保持一致
- 关系遵循 03 文档第 4 节：User → Profile / Goal → Project → Task，Conversation / Growth Log / Memory 挂 User 下

## 5. AI Layer 设计

### 流程

```
用户输入
    ↓
读取上下文：
    User Profile
    Goal
    Project State
    History
    ↓
生成 Prompt
    ↓
调用 LLM
    ↓
返回建议
```

### AI 为什么需要上下文

| 原因 | 说明 |
| --- | --- |
| 个性化 | 无上下文则无法区分用户状态，回答是泛化的 |
| 目标相关性 | 建议需围绕当前目标，而非通用建议 |
| 连续性 | 需基于历史记录判断进度，避免重复或倒退 |
| 行动导向 | 只有结合项目状态才能给出"下一步行动"而非百科式回答 |

结论：上下文 = User Profile + Goal + Project State + History，是 AI 导师与普通聊天机器人的本质区别。

## 6. Memory System 记忆系统

### V1 简单方案

不使用复杂知识库（向量库 / RAG / 图谱），仅使用结构化存储 + 上下文组装。

### 临时记忆

| 内容 | 说明 |
| --- | --- |
| 当前聊天 | 本次会话的消息上下文（Conversation） |
| 当前任务 | 正在推进的任务（Task） |

### 长期记忆

| 内容 | 说明 |
| --- | --- |
| 用户偏好 | 学习方式、决策偏好（User Profile） |
| 长期目标 | 目标与状态（Goal） |
| 重要经验 | 关键结论、成长记录（Growth Log / Memory） |

### 实现方式（V1）

- 长期记忆存 PostgreSQL（结构化字段）
- 每次请求由 Backend 从数据库读取，组装进 Prompt
- 不做向量检索，不做记忆自动写入模型

## 7. 一次完整请求流程

示例：用户提问"我今天应该做什么？"

```
用户提出问题（Frontend）
    ↓
发送请求到 Backend
    ↓
Backend 读取数据库：
    User Profile / Goal / Project State / History
    ↓
构建 Prompt（含上下文）
    ↓
调用 AI（LLM API）
    ↓
返回结果（建议：今日行动 / 原因 / 完成标准）
    ↓
Backend 保存记录（Conversation / 待办 Task）
    ↓
Frontend 展示结果
```

| 环节 | 动作 | 产出 |
| --- | --- | --- |
| Frontend | 用户输入消息 | 请求体 |
| Backend | 读取状态并组装上下文 | Prompt |
| AI Layer | 调用 LLM | 建议文本 |
| Backend | 解析并保存 | Conversation 记录 |
| Frontend | 展示建议 | 用户可见结果 |

## 8. 技术选型建议

| 层 | 技术 | 说明 |
| --- | --- | --- |
| Frontend | Next.js | 适合快速开发 AI 应用（React 生态、页面路由） |
| Backend | FastAPI | Python 生态适合 AI 开发，API 定义简单 |
| Database | PostgreSQL | 适合结构化数据，关系模型匹配 |
| AI | LLM API | 调用现成模型，无需自行训练 |

选型原则：全部为成熟、资料多、初学者可上手的技术；V1 不引入额外中间件（消息队列、缓存、微服务等）。

## 9. V1 暂不实现内容

| 内容 | 说明 |
| --- | --- |
| 多 Agent 系统 | 单一 Agent 即可跑通闭环 |
| 自训练模型 | 使用现成 LLM API |
| 复杂 RAG 知识库 | 结构化上下文足够 V1 |
| 自动爬虫 | 不做自动联网采集 |
| 社区系统 | 单人使用 |
| 复杂权限系统 | 单用户 / 简单登录 |

以上内容未来按需逐步扩展，不进入 V1 范围。

## 11. 开发学习路线

按初学者可执行顺序设计，每阶段产出可运行成果。

| 阶段 | 主题 | 内容 | 阶段产出 |
| --- | --- | --- | --- |
| 阶段 1 | 开发环境 | Python、Node.js、Git、VS Code | 环境可用，能跑通 Hello World |
| 阶段 2 | 前端基础 | HTML、CSS、JavaScript、React / Next.js | 静态工作台页面 |
| 阶段 3 | 后端基础 | Python、FastAPI、API 概念 | 可调用的 API 接口 |
| 阶段 4 | 数据库 | SQL、PostgreSQL、数据关系 | 数据表建好，可读写 |
| 阶段 5 | AI 接入 | API 调用、Prompt 设计、上下文管理 | AI 对话可用 |
| 阶段 6 | 记忆系统优化 | 上下文组装、状态读取 | AI 建议结合用户状态 |
| 阶段 7 | 产品体验优化 | 页面打磨、流程完善 | 完整闭环可日常使用 |

学习原则：每阶段先跑通最小可用版本，再进入下一阶段；全程围绕"AI 导师"这一个项目学习，不贪多。
